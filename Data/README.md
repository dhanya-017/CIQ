# Data folder

The claims data is patient-level, so **nothing in this folder except this README and the `.gitkeep`
placeholders is committed to git**. Each user supplies the data locally.

| Folder | Contents | Who creates it |
|---|---|---|
| `real_data/` | **The one input file:** `master_nsclc.csv`, the NSCLC claims extract | You copy it from the secure data share |
| `reference/` | Optional `patient_age.csv` (`patient_id,age`), used when the claims file has no age column | You copy it from the data share |
| `warehouse/` | `ciq.duckdb`, the analytics warehouse; `backup/` holds the previous builds | Generated by the build |
| `conversations/` | Saved CIQ chat sessions (`<id>.json`), including query results | Generated by the app |
| `cohorts/` | Saved HCP cohorts (`cohorts.json`) from the Compare screen | Generated by the app |

Public reference files (the drug dictionary, and ICD-10-CM and HCPCS descriptions) live in `ciq/reference/` in git,
not here.

## Plug and play: using a new or updated claims file

1. Put the file in `Data/real_data/` as `master_nsclc.csv`, **or** anywhere else and point to it:
   - set `CIQ_INPUT=path/to/file` in `.env`, or
   - run `python -m ciq.build.build_warehouse --input path/to/file`.
2. **Accepted:**
   - File types: `.csv`, `.csv.gz`, `.tsv`, `.txt` or `.parquet`.
   - Headers: any case and spacing, plus common alternatives, e.g. `Service Date` / `service_from_date` for
     `svc_dt`, `payment_type` for `plan_name`. The full list is in `ciq/build/inputs.py` (`ALIASES`).
   - Dates: ISO (`2026-03-30`, with or without time) or US (`03/30/2026`).
   - An `age` column, if present, is used directly.
3. Check it without building: `python -m ciq.build.build_warehouse --validate-only`. This reports rows, patients,
   dates, sources and cohort size. It **stops** on a missing required column, unreadable dates (over 5% of
   rows), unknown `source` values or an empty cohort.
4. Start the app (`.\run.ps1` / `./run.sh`). It rebuilds automatically because the file changed (about 70 seconds).
   A failed build never replaces the working warehouse, and the previous warehouse is kept in `warehouse/backup/`.

**Required columns:** `patient_id`, `svc_dt`, `source` (`RX` / `MX_RX` / `MX_PX`), `diagnosis_code`, `code`.
**Optional:** `claim_id`, `code_description`, provider IDs, `plan_id`, `plan_name`, `days_supply`, `quantity`,
`refill_code`, `age`. See [docs/DATA_DICTIONARY.md](../docs/DATA_DICTIONARY.md).

## Without `patient_age.csv`

The build and every analysis still work. The only difference is that age is unavailable:
- demographics say so,
- age rows in comparisons show "—",
- age-based cohorts return a clear message.
