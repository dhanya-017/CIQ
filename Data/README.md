# Data folder

The claims data is patient-level, so **nothing in this folder except this README and the `.gitkeep`
placeholders is committed to git**. Each user supplies the data locally.

| Folder | Contents | Who creates it |
|---|---|---|
| `real_data/` | `master_nsclc.csv`: the NSCLC claims extract (15 columns). **Required - the default input** (`CIQ_SOURCE=master_nsclc`). `mx_nsclc.csv`: raw medical extract, used to enrich age and billing provider (recommended). | You copy them here from the secure data share |
| `master/` | `claims_master.parquet`: the v1 long-format claims master. Optional: fallback for code descriptions/age, and the input for the legacy build (`CIQ_SOURCE=claims_master`). | Copy from the data share if needed |
| `warehouse/` | `ciq.duckdb` (and `backup/` copies of earlier builds): the analytics warehouse (facts, dimensions, lines of therapy, `fn_*` stored functions) | Generated by `python -m ciq.build.build_warehouse` |
| `conversations/` | Saved CIQ chat sessions (`<id>.json`), including query results | Generated by the app at runtime |
| `cohorts/` | Saved HCP cohorts (`cohorts.json`) from the Compare screen | Generated by the app at runtime |

## Getting the data

1. Request access to the NSCLC claims extract from the data owner.
2. Copy `master_nsclc.csv` and `mx_nsclc.csv` into `Data/real_data/` (optionally `claims_master.parquet` into `Data/master/`). Use the secure share only; never email it or put it in git.
3. Run `python scripts/doctor.py` to check it, then `python -m ciq.build.build_warehouse` (about 2 minutes).

`scripts/doctor.py` checks the input file for the columns the build needs, and whether the enrichment files are present.
